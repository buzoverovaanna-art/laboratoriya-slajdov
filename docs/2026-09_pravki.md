## Блок А. Сдача работы: PDF, QR, ссылки

### А1. Экспорт в PDF — ✅ сделано 24.09.2026 (`pdf.py`, кнопка «PDF» на полке; печать через Chrome, текст в PDF выделяется, ~6 с на 9 слайдов). Тем же днём добавлена автоподгонка слайда под экран (`fit()` в `styles/common.py`) — закрывает половину Б5
- **Где:** новый файл `pdf.py` + роут в `app.py` рядом с `download_work`.
- **Как:** «напечатать» готовую презентацию безголовым браузером
  (Playwright уже в проекте): каждый слайд — страница 16:9. Вёрстку
  переделывать не нужно, PDF = точная копия.
- **Кнопка:** «Скачать PDF» рядом с скачиванием HTML.
- **Проверка:** в PDF все слайды, фон и шрифты на месте, текст читается.

### А2. QR-код
- **Где:** `app.py` (адрес в домашней сети уже умеет `wifi_address`),
  карточка работы на полке.
- **Как:** библиотека `qrcode` (добавить в `requirements.txt`), QR ведёт
  на адрес работы в домашней сети.
- **Нюанс:** под QR честно написать «работает, пока включён MacBook».
- **Проверка:** отсканировать с телефона в той же Wi-Fi.

### А3. Починка ссылок на слайды — ✅ сделано 24.09.2026 (обработчик `hashchange`; сдвига на единицу не было; у старых работ заработает после пересборки)
- **Где:** `styles/common.py`, конец JS-блока управления (~строка 130).
- **Сейчас:** слайд по ссылке `#5` выбирается только при загрузке,
  перелистывание адрес не обновляет, смена хэша без перезагрузки не
  работает. Подозрение на сдвиг на единицу: `#2` открывала 3-й слайд.
- **Как:** обработчик `hashchange` + запись номера слайда в адрес при
  перелистывании.
- **Проверка:** дописать в адрес `#5` — открылся пятый слайд;
  перелистнуть — адрес изменился.

## Блок Б. Качество готовой работы

### Б4. Фильтр картинок (самое важное)
- **Где:** `images.py` (`_search_images`, `_credit`) + `styles/engine.py`.
- **Что:**
  1. Приоритет источников: Википедия и Викисклад первыми; мемные сайты
     (imgur, пикабу, tenor вне мем-стиля и т.п.) — чёрный список.
  2. Подпись: «краткое название — сайт» до 40 знаков, не заголовок
     чужой статьи.
  3. Для «серьёзных» стилей (harry, business) — лёгкий сепия-фильтр ко
     всем картинкам (одна строка CSS в паспорте стиля).
- **Проверка:** пересоздать «Пётр Первый» — все картинки тематические,
  подписи короткие.

### Б5. Автопроверка вёрстки
- **Где:** новый `check_layout.py` (Playwright), предупреждение на полке.
- **Что:** после сохранения проверить каждый слайд: блоки не вылезают за
  экран; текст не обрезается; нет пересечения с панелью кнопок.
- **Проверка:** на нынешней «Пётр I» должно подсветиться 2 места —
  карточка на слайде 2 и источники на слайде 9.
- **Попутно:** починить эти два места в `styles/engine.py`: нижний
  отступ контентной зоны; источники вынести на отдельный слайд
  «Источники» после «Выводов», ссылки сократить до домена.

## Блок В. Устойчивость и выступление

### В6. Мини-редактор: три действия вместо перегенерации
- **Где:** роуты `/works/<id>/edit` в `app.py`; `update_work` в
  `generator.py` уже готова — подвести к ней форму.
- **Действия:** «другая картинка» (следующий результат поиска, без ИИ и
  лимитов) · правка текста слайда · удаление слайда с подтверждением.
- **Проверка:** заменить картинку Патрику на «Выводах» за 10 секунд
  без пересоздания презентации.

### В7. Режим репетиции с таймером
- **Где:** `styles/common.py` (JS) + заметки `notes` (уже генерируются).
- **Что:** кнопка «Репетиция»: таймер, шпаргалка «что говорить» на
  каждом слайде, в конце — список «слайд → время».
- **Проверка:** прогнать репетицию, увидеть разбивку по слайдам.

### В8. Дежурный режим без ИИ
- **Где:** обработка `fail` в `create` (`app.py`) + `build_deck`
  (`generator.py`) — генератор каркаса уже есть.
- **Что:** если ИИ недоступен (ключ, сеть, лимит) — не ошибка, а
  предложение «собрать каркас»: структура слайдов в выбранном стиле с
  подсказками «впиши сам».
- **Проверка:** временно переименовать ключ GigaChat → каркас, а не ошибка.

## Вкладки и экраны приложения

Сейчас всё приложение — одна длинная страница. Каркас: нижнее меню
из 5 вкладок (планшет, крупные иконки).

1. **🏠 Главная / Создать** — нынешняя форма из пяти шагов.
2. **📁 Мои работы** — полка выносится сюда: фильтр «все / мои / по
   предмету» (профили уже в `students.json`); кнопка «Дублировать»;
   обложки-превью первой страницы (скриншот Playwright при сохранении).
3. **🎤 Репетиция** — вкладка-тренажёр: выбрать работу → шпаргалка +
   таймер; запись с микрофона планшета и прослушивание (MediaRecorder,
   всё в браузере).
4. **🎴 Копилка фактов** — все факты из всех презентаций складываются в
   коллекцию карточек «вопрос — ответ»: режим карточек и мини-игра.
   Платформа становится тренажёром для повторения.
5. **⚙️ Настройки** — переключатель темы приложения (`home-eco.css` и
   `home-harry.css` уже написаны, переключателя нет); редактирование
   списка учениц; остаток дневного лимита (`usage.json` уже пишется);
   статус ИИ («готов / ищем ключ / офлайн») до начала работы.

### Улучшения существующих экранов
- Автосохранение черновика формы в `localStorage`.
- Экран ожидания с честными шагами от сервера: «ищу материал → читаю →

- Вкладка «Помощь»: инструкция картинками + «если не работает» с

## Фишки с GitHub (исследование 22.09.2026)

Источники: banana-slides (15,6k★, AGPL — только идеи), presenton
(10,7k★, Apache-2.0), presentation-ai (3k★, MIT), mckinsey-pptx (588★,
MIT), ppt-agent-skill (~150★, MIT).

### Первый приоритет (дёшево и ценно)
1. **План перед генерацией** (presentation-ai, ppt-agent-skill): после
   пяти шагов ИИ показывает план — заголовки по одному предложению;
   девочка правит план, затем создаются слайды. Экономит лимиты, учит
   структуре. Один экран-подтверждение между шагом 5 и «Создать».
2. **Пересоздание одного слайда** (presenton): кнопка «↻ переделать
   слайд» рядом с мини-редактором — ИИ переписывает только его. Токенов
   в ~10 раз дешевле полной генерации.
3. **Галерея раскладок по типу содержания** (mckinsey-pptx: 40 шаблонов;
   ppt-agent-skill: бенто-каркасы): добавить «до/после» со стрелкой,
   «большая цифра со стрелками ▲▼», «плюсы и минусы», «ступени-дорожка»,
   «матрица 2×2». Главная идея: движок сам выбирает раскладку по форме
   данных (даты → лента времени, сравнение → «до/после»).

### Второй приоритет (заметнее, дороже)
4. **Правка фразой** (banana-slides): поле «скажи, что поменять» —
   «сделай третий слайд короче» — ИИ правит готовую презентацию.
   Надстройка над мини-редактором и GigaChat.
5. **Библиотека материалов** (banana-slides): загруженные фото и тексты
   сохраняются в общую полку `materials/` и переиспользуются между
   презентациями.
6. **«Эхо обложки» и «ритм плотности»** (правила ppt-agent-skill):
   финал повторяет оформление титульного слайда; два плотных слайда
   подряд запрещены. Строки логики в `generator.py`/`engine.py`.
7. **Самопроверка по каталогу дефектов** (ppt-agent-skill: 8 типовых
   болезней слайдов, чинятся по порядку): развить Б5 — «слайд пустой
   наполовину», «два одинаковых слайда подряд», «слабый контраст».

### Roadmap (в описание проекта «что дальше»)
- **«Стиль по картинке»** — ключевая фишка banana-slides и presenton;
  наш план подтверждён лидерами, поднять в очереди.
- **Видео-доклад с озвучкой** (banana-slides: MP4 с закадровым голосом
  и субтитрами) — дорого, но заявить в roadmap.
- **Графики на чистом CSS/SVG** (ppt-agent-skill: 18 типов без JS) —
  когда режим «по учебнику» даст проверенные цифры; график только из
  проверенных чисел (честность Сценариста).

### Подсмотрели и сознательно не берём
React/Next.js, PostgreSQL, Docker, многопользовательские воркспейсы,
MCP-сервер — архитектура облачных продуктов. Сила нашей платформы —
один Python-файл, домашний Wi-Fi, нулевая стоимость. Редактируемый
PPTX-экспорт — месяцы работы; пока хватает PDF.
